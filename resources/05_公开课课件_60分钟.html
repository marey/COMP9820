① 开场：一门"没有考试"的课

00:00 – 05:00

先打破预期：这不是编程课，也不是背理论的管理课。

"You cannot use Agile, you can only be Agile."—— 讲师开宗明义：敏捷是哲学不是流程
  • 不教编程、不教 Web 开发——默认你已有编程基础（COMP9021 或同等）。教的是：多人协作时如何管理代码、管理项目、管理人。
  • 没有期末考、没有 quiz、lab 不计分。全部 100% 来自一个小组软件项目。
  • 把小组当作创业公司：每个人都是经理，每个人都写代码——不写代码就学不会管理代码、处理冲突。

🎤 开场互动建议：举手调查"有多少人用过 Git 的分支和 Merge Request？"——引出这门课解决的真实痛点。

② 课程是干啥的：一个项目、三个 Sprint

05:00 – 15:00

唯一考核：随机组队 4–5 人，开发「Task Tracker」，分 3 个 Sprint 交付，每个 Sprint 末向扮演客户的 tutor demo。

项目背景故事

"Procrastination Warriors" 们用便利贴、聊天记录、截图记任务，结果任务遗忘、deadline 错过——于是你们要开发神奇的 Task Tracker：添加、编辑、删除、分配任务。讲师和 tutor 扮演客户："我有问题和需求，你来解决。"

难度最易（"easy marks"）更难最难
  • Week 1 lab 随机分组（公平起见），不能到场要提前邮件 tutor 保留位置。
  • 技术栈锁定 Python Flask + HTML/CSS：保证组里每个人都能贡献，而不是只有一两个会 JS 的人干活。
  • Starter code 已备好：app.py + templates/index.html + requirements.txt，GitLab 仓库每人已建。
  • 每个 Sprint 末 tutor 都给反馈——不会到期末才知道自己什么水平。

③ 课程重点：三大主题 + 九周地图 + 工具链

15:00 – 30:00

所有讲座、所有评分，都绕着三条贯穿主题转。

THEME 1

Traceability 可追溯

Issue ↔ MR ↔ Commit ↔ 测试 ↔ 报告，tutor 要能从仓库验证你做了什么，而不是推断。

THEME 2

Automation 自动化

pytest + CI pipeline + 覆盖率报告：main 分支永远是绿的，机器替你守门。

THEME 3

Psychological Safety 心理安全

敢说"我卡住了"、Retro 不指责、冲突先沟通。团队氛围本身就是被考核的工程实践。

你会带走的工具链（这门课最"值钱"的部分）

  • Git/GitLab 团队流：feature 分支 → 有意义的 commit → MR + peer review → 作者自己合并；分支名如 feature-add-task；绝不直接改 main。
  • 测试：pytest + conftest.py 的 client fixture 每测试前重置；从用户故事写测试，先核心再边界。
  • CI：根目录 .gitlab-ci.yml（python:3.11 → pip install → pytest），push/MR 自动跑，没绿勾不合并。
  • 覆盖率：pytest --cov --cov-report=term-missing，看 Missing 行补测试；后端目标 >70%，不追 100%。
  • 设计 7 问：唯一事实来源？够简单？过度/不足设计？相关靠近？在臆测未来？遵循惯例？——没有强测试不重构。
  • 风险登记表：每条风险 7 字段（If…then…because… / 可能性·影响 / Owner / 缓解或应急 / 证据 / 状态 / 最近评审）。

🎤 此处可现场演示 2 分钟：开一个 GitLab MR + 绿勾 pipeline 的真实页面，比十页幻灯片都直观。

④ 注意事项：扣分与踩坑高发区

30:00 – 42:00

先讲三条"红线"（直接 0 分级别），再讲五个高频小坑。

红线一 · DEMO 缺席 = 0 分

每个 Sprint 的 lab demo 全员必须到场，缺席该 Sprint 记 0 分（除非批准的 special consideration）。

红线二 · 不接受迟交

Push 到 main 即提交，评分取截止前 main 上最新 commit。所有组共用 CI runner——最后一刻集中 push 会排长队，别赌。

红线三 · AI 可用但必须声明、必须能解释

demo 时 tutor 可能要求你现场改一行代码验证是本人工作；解释不了 = 不了解自己的工作 = 抄袭，该 Sprint 记 0。不要合并任何自己没完全理解的 AI 代码。

五个高频小坑

  1. 站会必须发在 MS Teams（tutor 可见）。Discord / WhatsApp 出了冲突课程无法查证，不算证据；站会按个人计分。
  2. 过程证据要真实：真实案例——某组 lab 讨论质量很高，但会议纪要和 commit message 明显是 AI 批量生成、内容失实，反而拿了更低的分。
  3. 互评（Moodle）不交，拿不到 Retro 那 5 分——它本身保密不计分，但提交是拿分前提。
  4. 组员失联 48–72 小时：先关心安全、报告 tutor，然后当其不会回来继续推进。大多数冲突先直接礼貌沟通就能解决。
  5. 有疑问尽早发论坛/邮件，别写在反馈表里（讲师截止后才看得到）；每周一记得看 newsletter。
⚠ 文档误区

所有报告只有上限没有下限——"质量 > 数量"，不要交 20–30 页凑字数；讲师原话：短小的文档只要把故事讲清楚就够了。

⑤ 如何拿高分：评分哲学与实操清单

42:00 – 55:00

先理解"分数从哪来"，再给一张可执行的清单。

评分哲学：三句话

  1. 不按功能数量给分。官方原文："groups will not be penalised having a very simple or few stories"——奖励的是有说服力的用户价值故事 + 能跑通的流程 + GitLab 上可验证的过程证据。
  2. 可追溯性是评分主线。每个 rubric 都在问同一个问题：tutor 能不能沿着这条链验证你的工作——
Issue + 验收标准→ MR "Closes #n"→ Commit→ 测试 / CI 绿勾→ 报告 / README 链接
  1. 每个 rubric 分四档（Strong / Developing / Limited / Not demonstrated），官方指导："Use Strong as the target"。

分 Sprint 的高分策略

SPRINT 1

把"easy marks"全拿满

契约、Issue Board、站会"照做就得分"；Features Demo 只占 30 分中的 5 分。Sprint 1 平均分高于 HD——这里丢分最可惜。每人 ≥1 个合入 main 的 MR、每周 ≥2 次站会，机械地保证。

SPRINT 2

让 git 历史替你说话

TDD 的证明就是 git 历史（先提交测试再提交实现），不用另写文档。CI 必做、MR 必须 Closes #n、周会必须有纪要（出席人、决策、行动项）。

SPRINT 3

报告互相链接成网

README（用模板）链接风险报告和复杂度报告；Issue/MR 标注 "Mitigates R3"；后端覆盖率 >70%；正式 demo 讲"用户·问题·价值·决策"（8 分），不要做 feature 流水账。

个人分怎么拿（20 分常被忽视）

  • Portfolio 占 Sprint 3 个人分 6/10：写"我做了什么 → 创造了什么价值 → 学到了什么"，每个说法都附证据链接（issue/MR/commit/截图）；要有取舍与成长，不是流水账时间线。≤1000 词，Moodle 提交。
  • Git 贡献可归因：有意义的 commit + Sprint 3 至少一个 substantial MR，并和 issue/风险/故事对得上。
  • 站会规律参与：具体（"写了 2 个用户故事"而非"做了些东西"）、暴露 blocker、帮队友解 blocker。
✓ 一条隐藏加分逻辑

验收标准没达成不一定扣分——但你要能解释：是时间不够，还是判断它不重要而主动砍掉。会取舍、能说明理由，本身就是项目管理能力的证据。

⑥ 一页带走 + Q&A

55:00 – 60:00
保持回路短：Plan → Build → Test → Deploy → Reflect——这是 SPM 的心跳。—— 全课总纲
  • 这门课考的不是"你会不会写代码"，而是你的协作过程能不能被验证。
  • 三大主题：Traceability · Automation · Psychological safety。
  • 三条红线：demo 全员到场 · 截止即终点 · AI 必须声明且能解释。
  • 高分公式：用户价值故事 + 真实过程证据 + 全链路可追溯，Strong 为目标。
  • 按周计划表走就不会掉队；卡住了立刻说，别等 deadline 才说"我卡了两周"。

🎤 预留 3–4 分钟 Q&A。常见问题：随机组队遇到不干活的怎么办（沟通 → tutor → 个人分保护你）；没有前后端经验能拿高分吗（能，Sprint 1 功能只占 5 分）；能不能用 React（不能，锁定 Flask + HTML）。
