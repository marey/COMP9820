🎯 这门课是什么

  • 面向已有编程基础（COMP9021 或同等）的研究生；不教编程/Web 开发，教的是多人协作时如何管理代码、管理项目、管理人。
  • 唯一考核：4–5 人随机组队，用 Python Flask + HTML 开发 Task Tracker，分 3 个 Sprint 交付；每个 Sprint 末向扮演客户的 tutor demo。
  • 三条贯穿主题：Traceability 可追溯 · Automation 自动化 · Psychological safety 心理安全。

🛠 技术总结

  • Git/GitLab：feature 分支 → 有意义的 commit → MR + peer review → 作者合并；分支名 feature-add-task；Issue=工作、Commit=实现、MR=集成。
  • 测试：pytest；tests/test_app.py；conftest.py 的 client fixture 每测试前重置；从用户故事写测试，先核心再边界；全绿≠没 bug。
  • CI：根目录 .gitlab-ci.yml：image: python:3.11 → pip install -r requirements.txt → pytest；push/MR 自动跑，没绿勾不合并。
  • 覆盖率：pytest --cov --cov-report=term-missing|html；看 Missing 行补测试，后端目标 >70%，不追 100%。
  • 设计 7 问：唯一事实来源？够简单？过度/不足设计？相关靠近、无关分开？在臆测未来？遵循惯例？没有强测试不重构。
  • 持久化：json + pathlib，启动 json.load，变更后 json.dump；测试用 tmp_path。
  • 复杂度：松耦合、高内聚；圈复杂度参考上限 8–10；挑最复杂函数重构。
  • 风险：每风险 7 字段（If…then…because… / L·I / Owner / 缓解或应急 / 证据 / 状态 / 最近评审）。

⚠️ 注意事项（扣分高发）

  1. Push 到 main 即提交；不接受迟交；不要最后一刻推（CI runner 共享排队）。
  2. 每个 Sprint 的 lab demo 全员必到，缺席记 0 分。
  3. 站会在 MS Teams（tutor 可见），Discord/WhatsApp 不算证据；按个人计分。
  4. AI 可用但必须声明，且要能解释每一行；不合并不理解的 AI 代码；AI 生成的失实纪要会扣分。
  5. 不按功能数量给分：用户价值 + 过程证据才是分数；报告只有上限，质量 > 数量。
  6. 组员失联 48–72h：先关心安全、报告 tutor，然后继续推进；沟通能解决大多数冲突。
  7. 互评（Moodle）保密不计分，但不交拿不到 Retro 分。
  8. 有疑问尽早发论坛/邮件，别写在反馈表里；每周一看 newsletter。
