# COMP9820 公开课讲稿要点（60 分钟）

> 配套课件：`05_公开课课件_60分钟.html`
> 资料来源：`lectures/01–09` 课件整理、`springs/00–03` Sprint 指南、`04_课程宣传资料_A4.md`

## 时间轴

| 时间 | 环节 | 讲什么 |
|---|---|---|
| 00–05 | 开场 | 打破预期：无考试、不教编程，教管理代码/项目/人 |
| 05–15 | 课程是干啥的 | 1 个 Task Tracker 项目 × 3 个 Sprint，组分 80 + 个人分 20 |
| 15–30 | 课程重点 | 三大主题、九周地图、带走的工具链 |
| 30–42 | 注意事项 | 三条红线 + 五个高频小坑 |
| 42–55 | 如何拿高分 | 评分哲学三句话 + 分 Sprint 策略 + 个人分 |
| 55–60 | 一页带走 + Q&A | Plan → Build → Test → Deploy → Reflect |

## ① 开场（0–5 min）

- 金句开场："You cannot *use* Agile, you can only *be* Agile."
- 三个反差：无考试/quiz/lab 分；不教编程；把小组当创业公司，每个人都是经理、每个人都写代码。
- 互动：举手调查"用过 Git 分支 + MR 的有多少？"

## ② 课程是干啥的（5–15 min）

- 故事：Procrastination Warriors → Task Tracker（add/edit/delete/assign 任务）；tutor 扮客户。
- 考核表（讲三行即可）：
  - S1（W1–3，W4 一 12:00）组 25 + 个 5，最易，"easy marks"
  - S2（W4–6，W7 一 12:00）组 25 + 个 5，CI 必做
  - S3（W7–10，W10 五 17:00）组 30 + 个 10，最难，正式 demo
- Week 1 lab 随机分组；技术栈锁定 Flask + HTML（保证人人能贡献）；starter code 已备好。
- 每个 Sprint 末 tutor 给反馈，不会期末才知道水平。

## ③ 课程重点（15–30 min）

- 三大主题：**Traceability · Automation · Psychological safety**（所有评分绕它们转）。
- 九周地图快速过（W1 Git → W2 敏捷 → W3 故事/Retro → W4 TDD/CI → W5 覆盖率/可维护性 → W6 部署 → W7 持久化/复杂度 → W8 风险 → W9 回顾）。
- 工具链（最"值钱"部分）：
  - Git 团队流：feature 分支 → 有意义 commit → MR + peer review → 作者合并；绝不直接改 main
  - pytest + conftest fixture；CI：`.gitlab-ci.yml`，没绿勾不合并
  - 覆盖率 `pytest --cov`，后端目标 >70%，不追 100%
  - 设计 7 问；风险登记表 7 字段
- 建议现场演示 2 分钟：真实 GitLab MR + 绿勾 pipeline。

## ④ 注意事项（30–42 min）

三条红线（0 分级别）：
1. **Demo 缺席 = 该 Sprint 0 分**（全员必到）
2. **不接受迟交**：push 到 main 即提交；CI runner 共享，别最后一刻推
3. **AI 必须声明且能解释每一行**：tutor 可要求现场改代码；解释不了 = 抄袭 = 0 分

五个小坑：
1. 站会必须在 MS Teams（个人计分；Discord/WhatsApp 不算证据）
2. 过程证据要真实（真实案例：AI 批量生成的失实纪要 → 反而更低分）
3. Moodle 互评不交 → 拿不到 Retro 分
4. 组员失联 48–72h：关心安全 → 报告 tutor → 继续推进
5. 疑问尽早发论坛/邮件；别写反馈表；每周一看 newsletter

文档误区：报告只有上限没有下限，质量 > 数量。

## ⑤ 如何拿高分（42–55 min）

评分哲学三句话：
1. 不按功能数量给分——奖励用户价值故事 + 过程证据
2. 可追溯链是主线：Issue(+UAC) ↔ MR(`Closes #n`) ↔ Commit ↔ 测试/CI ↔ 报告/README
3. 四档 rubric，"Use **Strong** as the target"

分 Sprint 策略：
- **S1**：easy marks 全拿满（契约/board/站会照做就得分；功能只占 5/30；平均分 > HD）
- **S2**：git 历史替你说话（先提交测试再提交实现即 TDD 证明）；CI、`Closes #n`、周会纪要
- **S3**：报告链接成网（README 模板链接风险/复杂度报告；"Mitigates R3"；覆盖率 >70%；demo 讲用户·问题·价值·决策，占 8/15，别做 feature 流水账）

个人分 20 分：
- Portfolio 6/10：做了什么→价值→学到什么，每条附证据链接；≤1000 词，Moodle 交
- Git：substantial MR + 可归因 commit
- 站会：具体、规律、暴露/帮解 blocker

隐藏逻辑：验收标准没达成不一定扣分——能解释取舍理由本身就是 PM 能力证据。

## ⑥ 一页带走 + Q&A（55–60 min）

- 心跳：**Plan → Build → Test → Deploy → Reflect**
- 考的不是会不会写代码，而是**协作过程能不能被验证**
- 预置 Q&A：
  - 组员不干活？→ 先沟通 → tutor → 个人分保护你
  - 没有前后端经验能高分吗？→ 能（S1 功能只占 5 分）
  - 能用 React 吗？→ 不能，锁定 Flask + HTML
